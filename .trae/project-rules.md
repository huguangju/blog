# 博文润色项目规则

## 写作风格指南

### 语言风格

- **简洁干练**：避免冗余表达，每句话都有明确目的
- **结构清晰**：使用标题层级组织内容，逻辑递进
- **技术准确**：确保技术术语使用准确，代码示例可运行
- **读者友好**：考虑不同技术水平的读者，适当解释概念

### 文章结构

1. **引言**：简明扼要地介绍主题和目标
2. **核心内容**：按逻辑顺序展开，使用小标题分段
3. **代码示例**：提供完整、可运行的代码
4. **总结**：概括要点，提供进一步学习方向

### 格式规范

- 使用 Markdown 语法
- 代码块指定语言类型
- 重要概念使用**粗体**强调
- 使用有序/无序列表组织信息
- 适当使用引用块突出重点

## 内容质量标准

### 技术文章

- 提供背景知识和问题场景
- 解释技术原理和实现思路
- 包含完整的代码示例
- 分析优缺点和适用场景
- 提供相关资源链接

### 源码分析

- 明确分析目标和范围
- 从整体架构到具体实现
- 关键代码段配有详细注释
- 绘制流程图或架构图（如需要）
- 总结设计思想和可借鉴之处

### 读书笔记

- 概述书籍主要观点
- 提取核心概念和方法论
- 结合实际工作经验思考
- 提供个人见解和应用建议

### 生活记录

- 真实自然的表达方式
- 适当的情感色彩
- 有意义的思考和感悟
- 高质量的图片配图（如适用）

## 修改建议模板

### 结构优化

- 调整标题层级，确保逻辑清晰
- 重新组织段落顺序
- 添加过渡句连接各部分

### 语言润色

- 简化复杂句式
- 统一术语使用
- 增强表达的准确性
- 提升可读性

### 内容完善

- 补充必要的背景信息
- 添加代码示例或图表
- 完善总结和延伸阅读
- 检查技术细节准确性

## 审核检查清单

- [ ] 标题是否准确概括内容
- [ ] 结构是否清晰有逻辑
- [ ] 语言是否简洁准确
- [ ] 代码示例是否完整可运行
- [ ] 技术概念是否解释清楚
- [ ] 是否有拼写和语法错误
- [ ] 格式是否符合 Markdown 规范
- [ ] 是否提供了有价值的见解
